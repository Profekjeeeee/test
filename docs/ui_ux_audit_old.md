# UI/UX-аудит · Telegram Mini App «Стоматология»

Основано на статическом анализе кодовой базы (React / Next.js App Router / Tailwind). Дата аудита: 18.05.2026.

---

## Обзор зон покрытия

| Зона | Итог |
|------|------|
| Safe Areas (верх / низ, Toast над таббаром) | Найдены системные промахи: фиксированный Toast, многие шапки без `safe-area-inset-top` |
| Touch targets (≥ 44×44 px) | Критически узкая сетка зубной формулы; ряд вторичных кнопок 36 px и ниже |
| Цветовая консистентность (отказ от «старого» зелёного) | Явные `green-*` / `#00665E` в коде не обнаружены |
| Light / Dark (хардкоды) | Местами `text-gray-*`, `inline style` без пары под тёмную тему |
| Навигационные тупики | Нет явного «назад» на регистрации и частично на success-booking |

---

## Методология (кратко)

- Использованы правила проекта (`.cursor/rules`, `.cursorrules`): синий акцент, Toast в стиле Telegram над таббаром, без зелёного брендового.
- Touch target: ориентир **минимум 44×44 CSS px** (Apple HIG / практика TMA на iPhone ~390px ширины).
- Оценка сетки формулы: `max-width body` **390px** (`app/globals.css`), контент формулы **px-4** → условная ширина порядка **~358px** на **16** колонок зубного ряда ≈ **~22px** на ячейку (без запаса под 44px).

| № | Название | Путь | Описание UX-бага | Рекомендуемое решение (best practice) |
|---|----------|------|-------------------|----------------------------------------|

Для пациента вычислять высоту таббара из CSS-переменной или единого токена. Всегда суммировать `safe-area-inset-bottom`. |
| 2 | Зона нажатия на отдельный зуб формулы значительно меньше 44×44 px | `components/dental/PatientToothFormula.tsx` | Интерактивные зубы — это `button` с `w-full` внутри **16-колоночной** flex/grid-сетки на узком холсте; фактическая ширина **~20–24px**, высота по `aspectRatio` **~28–34px**: высокая вероятность **промахов и случайных соседних нажатий** (особенно у врача при редактировании в `PatientMedicalSheet`). | Компромисс TMA: (а) режим «зум-дуги» или горизонтальный свайп квадрантов с **крупнее** таргетами; (б) **невидимое расширение** hit-area (`min-w-[44px] min-h-[44px]` + отрицательные margin/visual offset); (в) режим списка 32 выбора с превью. |

## 🟠 Средняя критичность

| № | Название | Путь | Описание UX-бага | Рекомендуемое решение (best practice) |
|---|----------|------|-------------------|----------------------------------------|
| 3 | Toast: одна строка + центрирование — длинные сообщения обрезаются / уезжают | `components/ui/Toast.tsx` | Класс **`whitespace-nowrap`** при фиксированной нижней позиции и узком холсте TMA: длинные тексты ошибок из врача/Supabase становятся **нечитаемыми**. | **`whitespace-normal`**, **`max-width: min(calc(100vw - …), …)`**, **2 строки с line-clamp** или перенос; для критических ошибок — короткая строка + детали в модалке. |
| 4 | Визуальный стиль Toast не совпадает с регламентом проекта | `components/ui/Toast.tsx` + `.cursor/rules` | В правилах зафиксирован **Telegram-паттерн**: ширина почти на экран, **сочный синий** фон и т.д. Фактический Toast — **`bg-[#0F172A]/90`**, **не во всю ширину**, без иконки-галочки из спецификации. Риск расхождения ожиданий пользователя и бренда. | Привести к одному паттерну: **`left-4 right-4`**, **`bg-primary`**, типографика и иконка; отдельный стиль ошибки (`destructive`). |
| 5 | Шапки без верхнего safe-area под вырезы / статус-бар Telegram | `screens/SupportChat/page.tsx` (`pt-12`), `screens/Doctor/Cabinet/page.tsx`, `screens/Doctor/Cabinet/DoctorCabinetSkeleton` (`pt-12`), `screens/StaffMessages/page.tsx` (`pt-12` в не-embedded режиме), `screens/Admin/Dashboard/page.tsx`, `screens/03_Main/page.tsx` (`pt-6` без `safe-area`), `components/layout/Header.tsx` (липкий блок **без** `padding-top` с `safe-area`) | При открытии в **Telegram WebView** контент может **залезать под системную верхнюю зону / вырез** на части устройств. | Базово: **`pt-[max(12px, env(safe-area-inset-top))]`** или обёртка `TopSafeInset` для всех full-screen клиентских/стафф экранов. Для sticky `Header`: добавить `safe-area-inset-top` к внутреннему блоку. |
| 6 | Календарь врача: дни месяца и стрелки месяцев — высота ячейки 36 px | `screens/Doctor/Cabinet/DoctorMonthCalendar.tsx` | Кнопки дней **`h-9` (36 px)** и навигация **`w-9 h-9`**, что **ниже 44 px** при плотном `gap`; в сценарии «быстро ткнуть дату между приёмами» растёт число промахов. | Минимум **`min-h-[44px]`**, увеличить вертикальный `gap`; стрелкам добавить **`min-w-[44px] min-h-[44px]`** с визуально компактной иконкой внутри. |
| 7 | Вторичные действия в карточке записи на главной — 36 px высота | `screens/03_Main/page.tsx` | Кнопки **«Подробнее» / «Перенести»** класс **`h-9`**. | Перейти на **`h-11` (44px)** или оборачивать в hit-area (`py` + `-my`). |
| 8 | Переключатель табов «Предстоящие / Прошедшие» — ниже порога | `screens/07_My_Appointments/page.tsx` | Сегменты **`h-9`**. | `min-h-[44px]` + сохранить визуальную компактность через типографику, не через уменьшение таргета. |
| 9 | Плашки «Перенести / Отменить» у приёма врача — 36 px | `screens/Doctor/Cabinet/page.tsx` | **`h-9`** для частых действий в стресс-сценарии. | **`h-11`** или увеличенный **`py`** с flex center. |
| 10 | Глобальный «Назад» в `Header` — 36×36 px | `components/layout/Header.tsx` | **`w-9 h-9`**. Широко используется пациентскими экранами. | **`w-11 h-11`** (44) или **`min-w-[44px] min-h-[44px]`** с оптической компенсацией. |
| 11 | Кнопка «Записаться» в прайсе — микро-CTA | `screens/14_PriceList/page.tsx` (`PriceRow`) | **`h-7`** (~28 px) для коммерческого действия рядом с ценой. | Минимум **40–44 px** высоты; вторичную кнопку можно делать outline, но не уменьшать зону нажатия. |
| 12 | Экран регистрации: нет явного возврата к входу | `screens/02_Registration/page.tsx` | После перехода с `/auth` пользователь без **вторичной affordance «Назад к входу»** (есть только нативный жест Telegram / браузера). При ошибочном сценарии — ощущение «тупика». | Текстовая ссылка **`router.back()`** или `Link` на `ROUTES.auth` с **минимальной высокой строкой hit-area 44 px**. |
| 13 | Шаг OTP: действие «Изменить номер» — маленькая текстовая зона нажатия | `screens/02_Auth/page.tsx` | Кнопка оформлена как строка **`text-[13px] text-gray-400`**, без **`min-h-[44px]`** / паддингов — промах большим пальцем. | Сделать **полноширинный ghost-control** («вернуться и изменить номер») с вертикальным **`py-3`**. |
| 14 | Успех записи: шапка без «Назад» и вторичной навигации | `screens/Booking_Success/page.tsx` | `Header title="Готово"` **без** `showBack`; выход только через таббар / «На главную» / системный жест. | Явная **`showBack`** к `/booking` или **«К записям»** вторичным ghost; либо **автозакрытие** Mini App после успеха (политика TMA). |

## Дополнительно (соответствие недавним продуктовым изменениям)

| Тема | Наблюдение |
|------|------------|
| Смена палитры на синюю медицинскую | Подтверждено использование **`primary` (#248bcf)** и родственных утилит; **зелёных Tailwind-классов** в TSX/CSS репозитория **не найдено** (поиск по `green-`, `emerald-`, `#00665E`). |
| Toast «как в Telegram» над нижним таббаром | Реализация базового `Toast` **частично** расходится с текстом правил (цвет / ширина). Исключение: **`PatientMedicalSheet`** задаёт свой `className` с **`bg-primary`** и полноширинными отступами — ближе к целевому паттерну. |
| Flex-структура чата | `screens/SupportChat/page.tsx`: нижний **`pb-[max(1rem,calc(env(safe-area-inset-bottom,0px)+5.25rem))]`** + **`BottomBar`** — логика «ось снизу» учитывается лучше, чем в Toast; блок ввода **44px min-height**, кнопка отправки **`size-11`** — соблюдены ориентиры для композера сообщений. |

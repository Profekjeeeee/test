# Dental Mini App — Презентация продукта

> Материал для питчей клиникам, партнёрам и инвесторам.  
> Конвертируется в слайды (Google Slides / Pitch / Gamma) или используется как one-pager.

---

## Слайд 1 — Титул

**Dental Mini App**  
Цифровая экосистема стоматологической клиники в Telegram

- Запись · Медкарта · Финансы · CRM · Аналитика
- Для пациентов, врачей и администраторов — одно приложение

---

## Слайд 2 — Проблема

| Боль клиники | Как проявляется |
|--------------|-----------------|
| Разрозненные системы | Excel + мессенджеры + 1С + бумажные карты |
| No-show | 15–25% записей без напоминаний |
| Потеря пациентов | Нет сегментации и reactivation |
| Нет прозрачности | Владелец не видит KPI врачей в реальном времени |
| Telegram уже есть | Пациенты пишут в личку, данные теряются |

---

## Слайд 3 — Решение

**Единый Telegram Mini App** — без установки отдельного приложения.

```
Пациент          →  запись, формула, счета, чат, документы
Врач             →  календарь, медкарта, ординаторская, план лечения
Администратор    →  дашборд, CRM, финансы, аналитика, audit
```

Данные в **Supabase** (Postgres + RLS + Realtime), не в localStorage.

---

## Слайд 4 — Ключевые модули (реализовано)

| Модуль | Возможности |
|--------|-------------|
| **Запись на приём** | Выбор врача, слота, push в Telegram |
| **Медицинская карта** | Формула FDI, аллергии, история визитов |
| **Документы** | Supabase Storage — снимки, PDF |
| **Уведомления** | Cron: −24ч, −2ч, отмена/перенос |
| **Финансы** | Счета, платежи, эквайринг-ready |
| **CRM** | 6 сегментов, авто-кампании reactivation |
| **Аналитика** | KPI врачей, LTV, экспорт CSV |
| **Audit Trail** | Журнал изменений медданных |
| **Безопасность** | RLS, PIN, Telegram initData verify |

## Слайд 5 — Пациентский опыт

1. Открывает клинику в Telegram → Mini App
2. Видит ближайший приём и прогресс лечения
3. Записывается за 30 секунд
4. Получает напоминание с кнопкой «Подтвердить»
5. Оплачивает счёт онлайн (mock → YooKassa)
6. Чат с врачом и поддержкой в одном месте

**Конверсия:** нативный UX Telegram, без App Store friction.

---

## Слайд 6 — Кабинет врача

- Месячный календарь всех приёмов
- Медкарта пациента: формула, internal notes, аллергии
- История лечения по визитам
- План лечения — статичные этапы + из записей
- **Ординаторская** — внутренний чат + консilium с формулой
- Push при новой записи

---

## Слайд 7 — Админ-панель

### Дашборд
- Записи на сегодня, выручка, графики Recharts

### CRM (`/screens/admin/crm`)
- Сегменты: new · active · at_risk · dormant · high_value · debtor
- Ручной и авто-запуск кампаний в Telegram

### Аналитика (`/screens/admin/analytics`)
- KPI каждого врача: записи, завершения, отмены, выручка, конверсия
- Топ LTV пациентов

### Финансы + Audit
- Счета, просрочки, платежи
- Полный audit log медицинских изменений

## Слайд 8 — Технологии

| Слой | Стек |
|------|------|
| Frontend | Next.js 15, React 19, Tailwind 4 |
| Backend | Supabase Postgres, RLS, Realtime |
| Auth | Supabase Auth + Telegram initData |
| Deploy | Vercel + Cron |
| Интеграции | Telegram Bot API, эквайринг-ready |

**Архитектура:** REST API (`/api/appointments`, `/api/clients/*`), сервисный слой, единый формат ответов.

---

## Слайд 9 — Безопасность и compliance

- Row Level Security — пациент видит только свои данные
- Врач — только своих пациентов (через appointments)
- `internal_notes` защищены триггером от изменения клиентом
- Audit trail на med-таблицах с diff old/new
- PIN-защита после Auth (bcrypt, блокировка после 5 попыток)
- Telegram initData HMAC verify на сервере

## Слайд 12 — Конкурентные преимущества

1. **Telegram-native** — там, где уже сидят пациенты
2. **All-in-one** — не нужна связка CRM + мессенджер + Excel
